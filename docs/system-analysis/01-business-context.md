# 01. Бизнес-контекст

Версия 1.0 · Статус: готово к ревью · Пет-проект, документация — упражнение по системному анализу

## 1. Проблема

Студенты и начинающие специалисты не понимают, какие навыки действительно требуются на junior/intern-позициях в data- и product-аналитике:

- советы в чатах и на курсах противоречат друг другу;
- читать сотни вакансий вручную долго, выводы получаются субъективными;
- зарплатные ожидания не связаны с конкретными навыками.

IT Skills Radar превращает набор вакансий в структурированные данные и отвечает на четыре вопроса:

1. Какие навыки чаще всего встречаются в моей роли и на моём грейде?
2. Как меняется спрос на навык по месяцам?
3. Чем роли отличаются друг от друга по набору навыков?
4. Есть ли зарплатный сигнал, связанный с навыком?

## 2. Цели

| ID | Цель | Как измеряем |
|---|---|---|
| BG-01 | Показать частоту и динамику навыков по роли и грейду | Пользователь находит топ-10 навыков роли не дольше чем за 1 минуту с открытия дашборда |
| BG-02 | Дать осторожный зарплатный сигнал по навыку | Для каждой пары «роль + грейд + навык» показаны медианы с навыком и без него и дисклеймер «корреляция, не причинность» |
| BG-03 | Обеспечить воспроизводимую и проверяемую загрузку данных | Повторная загрузка того же файла не создаёт дублей; по каждой загрузке есть сводка `total/valid/invalid/loaded` |

## 4. Границы системы

### In scope

- Роли из справочника кода: `data_analyst`, `product_analyst`, `data_scientist`, `ml_engineer`, `other_data_role`.
- Грейды: `intern`, `junior`, `middle`, `senior`, `lead`, `unknown`.
- Загрузка подготовленных JSON/CSV через CLI `python -m app.services.ingestion` с режимом `--dry-run`.
- Rule-based нормализация ролей, грейдов, навыков, зарплат; очистка HTML.
- Хранение raw-payload (`raw_source_metadata`) и нормализованного слоя в PostgreSQL.
- Пять аналитических витрин `analytics.*`.
- REST API только на чтение (FastAPI) и дашборд Streamlit.

### Out of scope

- Причинные выводы о влиянии навыка на зарплату.
- Рекомендации курсов, персональные карьерные треки, личные кабинеты.
- Парсинг сайтов в обход правил источника.
- NLP/LLM-извлечение навыков, fuzzy matching заголовков (ограничения первой версии из `docs/decisions.md` исходного проекта).
- Конвертация валют: зарплатные витрины используют только `RUB` и период `month`.

### Будущие расширения (TO-BE)

Прямые коннекторы к API источников, загрузка по расписанию, событийная интеграция `vacancy.ingested.v1`, журнал загрузок и отклонённых записей — (проектное решение, в текущей реализации отсутствует). Подробности — в [03-process-bpmn.md](03-process-bpmn.md) и [07-integration.md](07-integration.md).

## 5. Допущения и ограничения

- Данные — подготовленная выборка, а не репрезентативный срез рынка.
- Навыки извлекаются правилами по словарю синонимов (10 канонических навыков), часть синонимов может теряться.
- Зарплата указана не во всех вакансиях, поэтому возможна ошибка отбора.
- Зарплатная премия — только корреляционный сигнал.
- Обязательные поля записи: `source_vacancy_id`, `title`, `company_name`. Остальные поля необязательны или получают значение по умолчанию (`unknown`).

## 6. Метрики успеха

| ID | Метрика | Целевое значение | Способ измерения |
|---|---|---|---|
| M-01 | Время до ответа «топ-10 навыков моей роли» | ≤ 1 мин | Юзабилити-проверка на 3–5 пользователях (проектное решение, в текущей реализации отсутствует) |
| M-02 | Дубли после повторной загрузки того же файла | 0 | `UNIQUE (source_name, source_vacancy_id)` + тест загрузки |
| M-03 | Доля валидных записей в загрузке | ≥ 95 % | `valid_records / total_records` из сводки ingestion |
| M-04 | Покрытие зарплатой (`salary_coverage`) в junior-срезе | Отображается для каждой роли; целевое ≥ 40 % (проектное решение, в текущей реализации отсутствует) | `analytics.junior_roles_overview` |
| M-05 | Время ответа API (p95) на выборку до 10 000 вакансий | ≤ 500 мс | Нагрузочный прогон после `make load-test-10k` (порог — проектное решение, в текущей реализации отсутствует) |
| M-06 | Прохождение CI | 100 % зелёных сборок в `main` | GitHub Actions |
| M-07 | Время развёртывания стенда с нуля | ≤ 10 мин | `docker compose up --build -d` + `prepare_demo` |
